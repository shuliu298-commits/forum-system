## 1. 设计目标与范围

### 1.1 目标

构建一个可演示、可自动测试的全栈论坛系统(教学/演示级),验证:

- 前后端分离架构(Flutter ↔ Spring Boot RESTful API)
- 多数据库架构(MySQL 用户域 + MongoDB 内容域)
- 工程化质量保障(lint + 行数检查 + 自动化测试 + CI)

### 1.2 范围(初版)

| 模块 | 范围 | 备注 |
|---|---|---|
| 用户 | 注册、登录、查询、修改、注销 | 完整 CRUD Demo |
| 论坛 | 帖子列表、发帖、评论、回复 | 帖子含嵌套评论 |
| 工程化 | lint / check / docker-test 脚本 | 含 CI 接入 |
| 部署 | dev 与 test 两套 docker-compose | 运行在 WSL Linux |

### 1.3 非目标(初版不实现)

- 图片/附件上传、富文本编辑器、全文搜索
- 点赞、关注、消息通知、权限管理(角色/RBAC)
- 性能压测、分布式部署、灰度发布

```
│  Flutter App (前端)                                                    │

│  ┌───────────────────┐   ┌──────────────┐   ┌──────────────┐          │
│  │ spring-boot-service│──▶│  mongodb     │   │  mysql       │          │
│  │  (Spring Boot)    │   │  帖子/评论    │   │  用户/账号    │          │
│  └───────────────────┘   └──────────────┘   └──────────────┘          │
└───────────────────────────────────────────────────────────────────────┘
```

### 2.1 数据主权划分

| 数据域 | 存储 | 理由 |
|---|---|---|
| 用户(账号、密码、资料) | MySQL | 强一致性、事务性、CRUD 明确 |
| 帖子/评论(嵌套结构) | MongoDB | 无 schema、嵌套文档天然贴合、字段扩展方便 |

**【决策】跨域一致性策略**:初版采用"应用层协调"(先写 MySQL 再写 Mongo,失败则回滚/日志告警),不做分布式事务。帖子中冗余存储 author 的 username 快照,避免每次查询帖子时跨库 join。

## 4. 后端设计

### 4.1 技术选型 【决策】

| 项 | 选型 | 说明 |
|---|---|---|
| 语言/构建 | Java 17 + Maven | 与 Spring Boot 3 匹配 |
| 框架 | Spring Boot 3.x(Web + Security + Validation) | |
| 持久化 | Spring Data JPA(MySQL)+ Spring Data MongoDB | |
| 身份认证 | JWT(无状态,HTTP Bearer) | 初版前后端分离最简单方案 |
| 密码存储 | BCrypt(Spring Security 内置) | 禁止明文 |
| 参数校验 | Jakarta Validation(@Valid) | |
| 测试 | JUnit 5 + MockMvc + Testcontainers(可选) | 见第 8 节 |
| 代码质量 | Checkstyle + SpotBugs + 自研行数脚本 | 见第 7 节 |

### 4.2 模块划分与分层

按业务域分包(**【决策】采用按业务域分包**,而非按技术层分包,便于各自 ≤800 行):

```
com.forum
├── common/    # ApiResponse、ErrorCode、GlobalExceptionHandler、BizException
├── config/    # SecurityConfig、CorsConfig、WebConfig
├── user/
│   ├── controller/  UserController
│   ├── service/     UserService、AuthService
│   ├── repository/  UserRepository (JPA)
│   ├── entity/      User
│   └── dto/         RegisterRequest、LoginRequest、UpdateUserRequest、UserResponse
└── post/
    ├── controller/  PostController、CommentController
    ├── service/     PostService、CommentService
    ├── repository/  PostRepository (Mongo)
    ├── entity/      Post、Comment
    └── dto/         CreatePostRequest、CreateCommentRequest、PostResponse、CommentResponse
```

**行数约束落地方式**(≤800 行/文件):

- Controller 只做参数校验与结果包装,业务全部下沉 Service;
- Service 拆分为 PostService / CommentService / UserService / AuthService;
- 配置类独立文件;超过 600 行即启动拆分子服务或辅助类(如 `PostAssembler`)。

### 4.3 统一响应与异常处理

所有接口返回统一 JSON:

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 40001 | 参数校验失败 |
| 40100 | 未登录 / Token 无效 |
| 40300 | 无权限 |
| 40401 | 资源不存在 |
| 40901 | 用户名已存在 |
| 50000 | 服务器内部错误 |

实现:`GlobalExceptionHandler`(`@RestControllerAdvice`)统一捕获 `BizException`、`MethodArgumentNotValidException`、`Exception`。**【决策】HTTP 状态码同时按语义返回(200/400/401/404/500),body 内 code 用于业务细粒度区分。**

### 4.4 认证设计 【决策】

- `POST /api/auth/login` 返回 `{ token, userId, username }`(JWT,有效期 24h);
- 除 `POST /api/auth/**`、`GET /api/posts/**`(游客可读)外,均需携带 `Authorization: Bearer <token>`;
- 初版不做刷新 Token / 角色权限,注销用户后 Token 失效通过"查询用户不存在即拒绝"实现(不做黑名单)。

### 4.5 API 设计总览

#### 4.5.1 用户模块(`/api/users` 与 `/api/auth`)

| 方法 | 路径 | 说明 | 请求体 | 响应 data |
|---|---|---|---|---|
| POST | `/api/auth/register` | 注册 | `{username, password}` | `UserResponse` |
| POST | `/api/auth/login` | 登录 | `{username, password}` | `{token, userId, username}` |
| GET | `/api/users/{id}` | 查询用户 | - | `UserResponse` |
| PUT | `/api/users/{id}` | 修改用户名/密码 | `{username?, password?}` | `UserResponse` |
| DELETE | `/api/users/{id}` | 注销(软删除+删帖) | - | 无 |
| GET | `/api/users` | 用户列表(Demo) | - | `List<UserResponse>` |

规则:

- `username`:`[a-zA-Z0-9_]{3,20}`,唯一;`password`:长度 6~32,存 BCrypt;
- 注销采用**软删除**(`deleted=1`),同时删除该用户所有帖子与评论(初版直接物理删除 Mongo 文档);
- 修改密码需校验旧密码(旧密码字段 `oldPassword`)。

#### 4.5.2 帖子模块(`/api/posts`)

| 方法 | 路径 | 说明 | 请求体 | 响应 data |
|---|---|---|---|---|
| GET | `/api/posts` | 帖子列表(分页) | - | `{items:[PostSummary], total, page, size}` |
| GET | `/api/posts/{id}` | 帖子详情(含评论) | - | `PostDetail` |
| POST | `/api/posts` | 发帖(需登录) | `{title?, content}` | `PostDetail` |
| DELETE | `/api/posts/{id}` | 删帖(作者或管理员) | - | 无 |

#### 4.5.3 评论模块(`/api/posts/{id}/comments`)

| 方法 | 路径 | 说明 | 请求体 | 响应 data |
|---|---|---|---|---|
| POST | `/api/posts/{id}/comments` | 发表评论 | `{content}` | `CommentResponse` |
| DELETE | `/api/comments/{postId}/{commentId}` | 删除评论 | - | 无 |

规则:

- 内容长度 1~2000 字,非空;
- 评论直接嵌套在 Post 文档的 `comments` 数组内(初版单层评论,不实现楼中楼);
- 分页:`page`(从 0 起)、`size`(默认 10,上限 50),排序按 `createTime desc`。

### 4.6 数据模型设计

#### 4.6.1 MySQL:`user` 表

```sql
CREATE TABLE user (
    id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(20)  NOT NULL UNIQUE,
    password    VARCHAR(100) NOT NULL,           -- BCrypt
    deleted     TINYINT      NOT NULL DEFAULT 0, -- 0 正常 1 注销
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
                       ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 4.6.2 MongoDB:Post 文档

```json
{
  "_id": "ObjectId(...)",
  "authorId": 1,
  "authorName": "Tom",
  "title": "今天学习Spring Boot",
  "content": "...",
  "createTime": "2026-01-01T10:00:00Z",
  "updateTime": "2026-01-01T10:00:00Z",
  "comments": [
    {
      "commentId": "ObjectId(...)",
      "userId": 2,
      "userName": "Alice",
      "content": "很好，加油",
      "createTime": "2026-01-01T10:05:00Z"
    }
  ]
}
```

索引:`{createTime: -1}`(列表排序)、`{authorId: 1}`、`{comments.commentId: 1}`。

#### 4.6.3 关键数据流

1. **注册**:校验唯一性 → BCrypt 加密 → 写入 MySQL。
2. **登录**:查 MySQL → 校验 BCrypt → 签发 JWT。
3. **发帖**:鉴权 → 从 token 取 userId → 冗余 authorName → 写 Mongo。
4. **评论**:鉴权 → 校验帖子存在 → `$push` 进 comments → 返回评论。
5. **注销用户**:MySQL 软删除 → 批量删除该用户 Mongo 帖子(含其评论)→ 返回。
6. **删帖**:校验作者 → 删除 Mongo 文档(级联删除其评论)。

### 5.3 网络层设计

```dart
class ApiClient {
  final Dio _dio;
  Future<T> get<T>(String path, ...);   // 自动解 ApiResponse
  Future<T> post<T>(String path, body);
  Future<T> put<T>(...);
  Future<T> delete<T>(...);
}
```

- `BaseOptions.baseUrl` 从 `ApiConfig` 读取(默认 `http://localhost:8080/api`);
- 拦截器:请求前附加 Token;响应统一判 `code != 0` 抛出 `ApiException`;
- `40100` 统一处理:清 Token、跳转登录页。

## 8. 自动化测试设计

### 8.1 check 流程(`scripts/docker-test/check.sh`)

```
启动 docker-compose-test(Mysql/Mongo/Backend)
   ↓
初始化数据库(init.sql + mock-data.json)
   ↓
后端健康检查等待(重试 N 次,GET /api/health)
   ↓
执行接口测试(见 8.3)
   ↓
输出测试结果 → 退出码(0 通过 / 1 失败)
   ↓
清理容器(docker compose down -v)
```

### 8.2 Mock 数据

- `deploy/init/init.sql`:建表 + 3 个用户(Tom/Alice/Bob,固定 BCrypt 密码);
- `deploy/init/mock-data.json`:5 篇帖子 + 每帖 2~3 条评论(与框架示例一致)。

### 8.3 接口测试方案 【决策】

| 方案 | 说明 |
|---|---|
| **主方案**:Java 集成测试(JUnit5 + MockMvc,`@SpringBootTest` + test profile) | 随 `mvn verify` 执行,覆盖核心业务 |
| **补充方案**:脚本端到端测试(`scripts/docker-test/run-api-tests.sh` 内嵌 curl 断言) | 验证容器编排、Mock 数据、真实链路 |

**测试覆盖清单**:

| 编号 | 用例 | 预期 |
|---|---|---|
| T01 | 注册新用户 | code=0,返回 userId |
| T02 | 重复注册同名用户 | 40901 |
| T03 | 登录成功 / 密码错误 | 返回 token / 40100 |
| T04 | 查询用户 / 查不存在用户 | 200 / 40401 |
| T05 | 修改用户名密码 | 新值生效 |
| T06 | 注销用户 | 用户 deleted=1,其帖子被清 |
| T07 | 帖子列表(分页/排序) | 返回 mock 数据 |
| T08 | 发表评论 + 读取详情 | 评论出现在 comments |
| T09 | 未登录发帖/评论 | 40100 |
| T10 | 数据持久化(重启容器后列表仍在) | 数据不丢 |

```
│   CI 上仅保留 Dart 静态检查(若提供容器)      │
└──────────────────────────────────────────────┘
```

CI 失败示例(输出到日志 + PR 评论):

```
CI FAILED
Reason:
UserController.java: 950 lines > 800 limit
```

> 说明:Flutter Windows 构建链依赖本地 SDK,故 **实际编译发布保留在 Windows 环境手动执行**;CI 负责源码级检查与后端全链路验证。

### 9.2 本地 CI 模拟

`scripts/check/check.sh` 即 CI Stage 1~3 的本地等价物,保证"本地通过 = CI 通过"。

## 10. Git 开发规范

### 10.1 分支模型

```
main            # 稳定,仅合入 release,打标签
  └─ develop    # 集成分支
       └─ feature/*   # 功能分支,如 feature/user-crud
```

### 10.2 流程

```
develop → 创建 feature/* → 开发 → 提交 PR → CI 检查 → merge develop
                                                      ↓
                                              release 打 tag
```

### 10.3 提交规范 【决策】引入 Conventional Commits

```
feat(user): 新增用户 CRUD 接口
fix(post): 修复分页越界问题
chore(scripts): 新增行数检查脚本
docs: 更新设计文档
```

## 12. 风险与待确认项

| 项 | 风险/问题 | 建议 |
|---|---|---|
| 跨库一致性 | 注销用户涉及 MySQL + Mongo 两步 | 初版接受最终一致 + 告警日志;后续可引入 Outbox/任务补偿 |
| 前端 Windows 构建无法进 CI | 只能手动编译 | 保持源码级检查;后续可在 Linux 容器内做 `flutter build web` 兜底 |
| Mongo 嵌套评论的并发 | 高并发下 `$push` 需 atomic | 初版可接受;后续改为子集合 + 索引 |
| 软删除后用户名唯一冲突 | 注销用户占用用户名 | 初版允许复用(软删后释放),设计时在 service 层处理 |
| Token 无状态失效 | 用户注销后旧 Token 仍可用 | 已通过"用户不存在即拒绝"缓解,后续可加黑名单 |
